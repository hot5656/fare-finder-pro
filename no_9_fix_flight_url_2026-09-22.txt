    if (!last) return true;                              // 從沒通知過 → 一定寄
    const hoursSince = ...;
    if (hoursSince >= NOTIFY_FLOOR_HOURS) return true;    // 距上次通知 ≥24 小時

● 對,你這樣做通常也不會補發新通知——原因是
  dedup(去重)判斷完全跟「目標價」無關,只跟「這次抓到的票價 vs.
  上次寄信時的票價」有關。

  看 flight-parser/index.ts:208-219:

  for (const sub of subs) {
    if (Number(sub.target_price) >= cheapest.price) {   // 
  只用來決定「算不算達標」
      matches.push({ ...sub, cheapest, cheapest_usd });
    }
  }

  target_price 只用在「這次抓到的票價是否 ≤ 目標價」這個門檻上,一旦達標,丟進
  matches 給 flight-notification。而 flight-notification 的 shouldSend()
  完全不知道、也不管你的 target_price 是多少或有沒有被更新過,它只比對:

  - 上次寄出時記錄的票價(notification_history.price)
  - 這次抓到的票價(cheapest.price)
  - 上次寄信距今幾小時

  以你的東京訂閱為例:上次寄信票價 6610、24 小時內、這次票價還是 6610 →
  就算你把目標價從 7000 改成
  8000(讓「有沒有達標」這件事更容易成立),抓到的票價依然是
  6610,跟歷史紀錄比對「沒有變化」,一樣會被 dedup 擋掉。

  唯一的例外:如果你把目標價調到某個「以前從沒達標過」的水準(例如以前設 5000
  從沒達標,notification_history 完全沒有這條 route 的紀錄),那下次 parser
  跑到、抓到票價 ≤ 新目標價時,因為歷史是空的(last 是 null),shouldSend()
  會直接回傳 true,馬上寄信——這時候才會因為「改目標價」而觸發新通知,但本質上是「
  這是這條路線第一次達標」,不是「改目標價」本身讓系統重新計算。

  換句話說:改目標價不會重置 24
  小時計時器,也不會讓已經比對過的同一個價格重新觸發通知。
