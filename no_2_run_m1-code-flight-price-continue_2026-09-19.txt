❯ service-role key 由何處取得 是何作用？                                        

⏺ 取得方式：

  Supabase Dashboard → 你的專案 (luugfvsrawnuzwpjvddt / demo_app) → Project 
  Settings → API → 在 "Project API keys" 區塊找 service_role / secret key，點
  "Reveal" 顯示。

  或用 CLI（你自己跑，我這邊被 sandbox 擋掉了）：
  supabase projects api-keys --project-ref luugfvsrawnuzwpjvddt --reveal

  作用：

  這是一把**完全繞過 RLS（Row Level Security）**的金鑰，等同資料庫的最高權限：

  - 一般前端用的是 anon/publishable key，所有查詢都受 RLS policy
    限制（例如「只能看到自己的訂閱」）。
  - service_role key 則無視所有 RLS policy，可以讀寫任何使用者的任何資料列。

  在這個專案裡它用在兩個地方：
  1. Edge Functions（flight-parser、flight-notification）內部驗證呼叫者身份 —
     function 內手動檢查 Authorization: Bearer <service_role_key>，只有帶這把
     key 的呼叫才被允許執行（因為它們要讀所有使用者的訂閱、寫入
     flight.notification_history，這些一般使用者都不該碰到）。
  2. pg_cron 排程之後也要用它，才能每 30 分鐘自動呼叫 flight-parser。

  風險提醒： 這把 key 絕不能出現在前端程式碼、瀏覽器、或 commit 進 git —
  一旦外洩，任何人都能繞過所有權限限制存取整個資料庫。這也是為什麼 Claude Code
  的 sandbox 把「reveal 這把 key」歸類為需要你手動操作的敏感動作。

  拿到 key 後，直接貼給我（或你自己跑 curl 測試），我可以繼續 TODO #2（驗證 Edge
  Function）跟 #3（接上 pg_cron）。

❯ 我是不是直接設到 Edge Function Secrets ? Ｓecrets name 為何?                  

⏺ 不用手動設定成 Edge Function Secret。

  它已經自動存在了 — Supabase 替每個 Edge Function
  自動注入這幾個環境變數，不用你手動加：
  - SUPABASE_URL
  - SUPABASE_SERVICE_ROLE_KEY ← 就是這把 key，function
    內部已經在讀這個名字（flight-parser/flight-notification 的程式碼都是
    Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')）
  - SUPABASE_ANON_KEY 等

  所以在 supabase secrets list 裡你看不到它，因為它不是「自訂
  secret」，是平台內建、每個 function runtime 都有的。

  那你 reveal 這把 key 要拿來做什麼？ 兩個外部呼叫的情境，key
  不會被「設定」進任何地方，只是當下使用：

  1. TODO #2：手動測試 function（curl） — 從你的終端機模擬「呼叫這個
     function」，key 直接放在 curl 指令的 header 裡，一次性使用：
  curl -X POST
  "https://luugfvsrawnuzwpjvddt.supabase.co/functions/v1/flight-parser" \
    -H "Authorization: Bearer <你 reveal 出來的 service_role key>"
  2. TODO #3：pg_cron 排程呼叫 — 這個才需要「存起來」，但存放位置是 Supabase 
     Vault（資料庫層的加密儲存），不是 Edge Function Secrets：
  select vault.create_secret('<service_role key>', 'flight_service_role_key');
     之後 pg_cron 排程的 SQL 會從 Vault 讀出來，動態組進 HTTP header 打給
     flight-parser。

  簡單說：Edge Function 本身不需要你設定它；你 reveal
  出來只是為了「你自己/pg_cron」能以合法身份呼叫這兩個 function。
