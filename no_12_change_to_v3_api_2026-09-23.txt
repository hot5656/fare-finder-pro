    連線，再加上 Gmail 的垃圾信掃描，才會出現在收件匣。一般要幾秒到一兩分鐘，40
    秒很常見。短時間內一直對同一個地址寄內容相同的信（這個地址昨天到今天手動寄了
    5 次），Gmail 有時會多檢查一下，就會再慢一點。
  - 對話串的影響：新信進的是舊的對話串，所以不容易一眼看出它剛到。

  之後測試時，按下按鈕後等 1 到 2 分鐘再看收件匣就可以。如果超過 5
  分鐘還沒收到，再去 Resend dashboard 查那封信的狀態。

⏺ 可以加，但有上限。資料來源 Travelpayouts
  提供的是快取的價格資料，不是即時訂位系統，所以只拿得到一部分欄位。

  現在用的 API（flight-parser 呼叫的 v1/prices/cheap）有這些欄位
  - airline：航空公司代碼，例如 CI、BR。信裡已經有顯示，但只是代碼。
  - flight_number：航班號碼。目前有回傳，但我們沒有用到。
  - departure_at / return_at：出發和回程的日期時間。信裡現在只顯示日期。
  - 它沒有抵達時間、飛行時間、轉機次數。

  如果改用 v3/prices_for_dates，可以多拿到
  - duration_to / duration_back（飛行時間），配合出發時間就能算出抵達時間
  - transfers / return_transfers：去程和回程的轉機次數
  - origin_airport / destination_airport：實際的機場，例如 TPE→NRT 或 TSA→HND
  - link：直接連到那一班航班的訂購連結，會比現在的搜尋頁準確

  做得到的內容：航空公司名稱（用代碼對照表轉成「中華航空」這類名稱）、航班號碼、
  去回程的出發和抵達時間、飛行時間、直飛或轉幾次、機場。

  限制
  1. 這些資料是其他使用者先前搜尋留下的快取，可能是幾小時到幾天前的。實際訂位時
     時間或班次可能已經變了，信裡要註明「僅供參考」。
  2. 抵達時間是用出發時間加飛行時間算出來的，時區要自己處理，可能跟航空公司公告
     的時間有幾分鐘誤差。
  3. 艙等、行李額度、剩餘座位都拿不到，這些要接航空公司或 GDS 的即時 API
     才有，那是另一個等級的串接。

  要做的話，要改 flight-parser（換成 v3 API、把更多欄位存進
  flight.routes）、flight-admin-notify 和 flight-notification
  的信件內容，而且需要一次資料表 migration。你決定要做再跟我說。

❯ ask only: 標示回程 有何意義 不是單程價格？                                    

⏺ 不是單程。NT$6,557 是來回票價，已經包含那一段回程航班。所以列出回程是在說明這
  個價格買到的是哪一趟回程，它本來就是票價的一部分。

  怎麼確認是來回票價
  - v1（/v1/prices/cheap）：預設就回傳來回票價，每筆都有 return_at（回程時間）和
    duration_back（回程飛行時間）。專案從 M1
    開始用的就是它，所以之前通知信裡的價格一直都是來回價。
  - v3：我設定了 one_way=false，讓它也查來回票，才能跟 v1 比較。v3
    預設是查單程。
  - 訂購連結：/search/TPE2910TYO02111，拆開是 TPE、10/29 出發、TYO、11/02
    回程、1 位旅客，就是那張來回票。
  - 信上的欄位名稱「票價（來回）」也是這個意思。

  如果想改成單程
  v3 可以改成 one_way=true 查單程，改動不大。但要考慮：
  - 單程通常比來回的一半還貴，也可能便宜（例如廉航）。總之價格基準會變。
  - 使用者設定目標價時，參考的是 dashboard 上的「最後查詢」價格，那一直都是來回
    價。改成單程後，價格可能突然跌到目標價以下，造成一批誤觸發的通知。
  - v1 沒辦法指定單程，改了之後對照區就不是同一種票價，比較沒意義。

  建議維持來回，只要讓使用者清楚知道是來回價就好，例如在 dashboard
  的價格旁加上「來回」字樣。要改單程或加標示的話跟我說。

❯ ask only:但一般若回程更改時間會不會影響價格？                                 

⏺ 會。來回票價是針對特定一組出發日和回程日算的，回程改期，價格通常就會變。

  購票前：選不同的回程日
  - NT$6,557 只適用於 10/29 出發、11/02 回程這個組合。在 Aviasales
    上改回程日，價格會重新計算，可能差很多。
  - 影響價格的因素包括星期幾（週五、週日回程通常較貴）、連假、剩餘的便宜艙位，還
    有停留天數（有些航空公司的票價規則會限制最短或最長停留）。

  購票後：更改已購機票的回程
  - 通常要付「改票手續費」加上「新舊票價差額」，金額由票種規則決定。
  - 通知信裡這種最低價，多半是廉航（例如樂桃）或限制多的便宜票種。這類票改期費用
    高，有的甚至不能改。
  - 我們拿不到票價規則，Travelpayouts 的資料不含這部分。

  這跟我們的通知有什麼關係
  - 通知判斷的是「這個月出發的來回票中，最便宜的那一組日期」。出發日和回程日是
    Travelpayouts 快取裡剛好最便宜的組合，不是使用者自己選的。
  - 所以日期彈性大的人最適合這個通知。已經有固定日期的人點進去，換成自己的日期後
    ，價格可能高於通知的價格。
  - 目前信裡寫的是「實際價格、時間與座位以訂購頁為準」，沒有明說「換日期價格會不
    同」。

  可以改善的方向
  1. 在信裡明講（最簡單）：例如「此價格僅適用於上列出發與回程日期，更改日期價格
     可能不同；廉航票改期通常需付手續費與差額」。
  2. 讓使用者設定行程條件：v3 可以指定確切的出發日和回程日（departure_at /
     return_at 可以精確到日），其他 endpoint
     也能按停留天數查。這要改訂閱表單和資料表，是比較大的功能。

  要做的話跟我說想做哪一種。
