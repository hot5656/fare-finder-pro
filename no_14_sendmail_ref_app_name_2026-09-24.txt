● 可以。最穩的方法是讓每個 app 觸發寄信時，自己在 redirect_to 帶上 app 
  名稱，hook 再從網址讀出來選標題。這樣跟網域完全脫鉤。

  做法：在 redirect_to 加上 ?app=

  1. 前端觸發寄信時，在網址後面加上 app 參數：
  // 註冊
  emailRedirectTo: `${window.location.origin}/?app=${APP_NAME}`
  // 忘記密碼
  resetPasswordForEmail(email, { redirectTo:
  `${window.location.origin}/auth/reset?app=${APP_NAME}` })
  2. hook 讀這個參數，再到白名單裡查對應的名稱：
  const APPS: Record<string, { sender: string; product: string }> = {
    "fare-finder-pro": { sender: "Flight Price Notifier 
  <noreply@roberthut.com>", product: "機票降價通知" },
    "project-management": { sender: "案件管理系統 <noreply@roberthut.com>",
  product: "案件管理系統" },
  };
  function resolveApp(redirectTo?: string, user?: { user_metadata?: { app?:
  string } }) {
    let app: string | null = null;
    try { app = new URL(redirectTo ?? "").searchParams.get("app"); } catch {}
    app ??= user?.user_metadata?.app ?? null;   // 其次：使用者資料裡的 app
    return (app && APPS[app]) || null;          // 對不到就用通用標題
  }
     標題可以寫成 `${cfg.product}｜確認你的帳號`。

  這樣做的好處
  - 不受網域影響：改成 flight.vercel.app、Vercel preview 網址、localhost
    都能正確判斷，也能分辨兩個都跑在 localhost 的 app。
  - 判斷的是「這次是哪個 app 寄的」：忘記密碼時也準確。如果只看
    user_metadata.app，多個 app 共用的帳號會顯示成最後一次註冊的那個 app。
  - 只接受白名單裡的 app：redirect_to 是使用者端可以改的值，所以不能把參數直接放
    進信件標題。對不到白名單就用通用標題，避免有人塞入任意文字。

  要注意的地方
  - 兩邊都要改：每個 app 的前端都要加上 ?app=。還沒改的 app 會先退回讀
    user_metadata.app，最後才用通用標題，不會直接壞掉。
  - Redirect URLs 規則：帶了查詢參數之後，https://domain/**
    這類規則應該還是能通過，但建議先在 localhost 實測一次，確認沒有被退回 Site
    URL。
  - Send Email hook 整個 project 只有一個：你貼的版本和本 repo 的 send-email
    如果都部署到同一個 slug，後部署的會蓋掉先部署的。建議合併成一支共用的
    hook，放在一個地方維護。
  - 你貼的這版會受改網域影響：它用網域關鍵字判斷，flight.vercel.app 不含
    fare-finder，改網域後會變成 "System Notification"。改用上面的 ?app=
    做法就不會有這個問題。
