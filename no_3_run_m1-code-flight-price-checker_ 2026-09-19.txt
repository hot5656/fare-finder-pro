❯ 開 PR 是何意思？                                                              

⏺ PR 是 Pull Request（合併請求），是 GitHub 上的功能。

  它是什麼
  - 你現在的工作在 multi-app 這個分支上，主線是 main。
  - PR 就是在 GitHub 上發出一個申請：「請把 multi-app 的修改合併進 main」。
  - 申請頁面會列出所有改動，你（或同事）可以檢查、留言，確認沒問題後再按「Merge
    」合併。

  它跟 push 的關係
  1. commit： 把修改存進你電腦上的 git 紀錄。這一步已經做完了。
  2. push： 把 commit 上傳到 GitHub，讓別人和 GitHub 上都看得到。這一步還沒做。
  3. PR： 在 GitHub 上申請把這個分支合併進 main。要先 push 才能開。

  你需要開 PR 嗎？
  - 只有你自己用、不需要審查： 不用開。你可以只
    push，或什麼都不做，程式碼在本機和已部署的 Supabase 上都已經是最新的。
  - 想留一個乾淨的紀錄，或之後要合併進 main： 就 push 再開 PR。
  - 注意： 目前 multi-app 分支的更動只在你的電腦上。Supabase
    上部署的函式已經是新版本，但 git 紀錄沒有備份到 GitHub。

  我不會自己 push 或開 PR，會等你決定。要我幫你 push 嗎？只 push、不開 PR
  也可以。

⏺ H3 和 H5 都是 M1 驗收清單（Section H）裡的項目，檢查「抓價程式 flight-parser
  比對訂閱者」時的兩個邊界情況。

  H3：USD 失敗時的行為
  - 功能： 系統用 TWD（新台幣）判斷是否達標，USD（美元）只是信裡的補充，例如「約
    US$206」。H3 要求 USD 抓不到時，仍然要用 TWD 正常通知，只是信裡不顯示「約
    US$」那一行。
  - 為什麼重要： 不能因為美元價格抓失敗（例如 API
    回傳空資料或被限流），就讓整次執行失敗，或讓訂閱者收不到通知。
  - 程式怎麼做： USD 的抓價外面包了 .catch()，失敗就當作 null
    繼續執行。寄信時只有 cheapest_usd 存在才會加美元那一行。
  - 為什麼沒實際測： 需要讓 USD
    的呼叫刻意失敗，例如暫時改程式碼，這樣會動到正式環境的函式。
  - 已有的間接證據： 「USD 成功」的情況已經看過（信裡有 US$243 和
    US$206）。缺的是「USD 失敗」那條路徑。

  H5：低於目前票價的目標價不該被通知
  - 功能： 比對方向要正確：只有「目標價 ≥ 目前最低票價」的人才會收到通知。
  - 舉例： 現在東京票價是 NT$6,556。
    - 目標價 8,000：會通知，這就是你現在的訂閱。
    - 目標價 5,000：票價還沒降到他想要的，不該通知，也不該寫入通知紀錄。
  - 程式怎麼做： 用 Number(sub.target_price) >= cheapest.price
    判斷，方向是對的。
  - 為什麼沒實際測： 需要另外新增一筆目標價很低的測試訂閱，例如目標
    4,000，才能確認它沒有被通知。目前資料庫只有你這一筆訂閱，而且它的目標價是高

❯ ask onlyl: 我無法透過 app web set 已訂閱 to 待追蹤？                          

⏺ 對，目前的 app 網頁做不到取消訂閱，這不是你操作錯了，而是 M1
  根本沒有這個功能。

  原因有兩層
  1. 畫面上沒有按鈕。 儀表板只有兩個動作：沒訂閱時按「開始追蹤」（新增），已訂閱
     時按「更新目標價」（更新）。程式碼裡只有
     upsert，沒有取消或刪除的寫法。這也符合 M1 skill
     的設計，它只規劃了「訂閱」和「更新目標價」。
  2. 資料庫也不允許。 flight.subscriptions 的資料列安全規則（RLS）只有三條：讀取
     、新增、更新自己的資料，沒有刪除規則。所以就算前端加了取消按鈕，現在送出刪
     除也會被拒絕。剛才清理測試資料，我才需要請你用 CLI（管理者身分）刪除。

  你說的「待追蹤」我猜是指還沒訂閱時的狀態，也就是卡片上顯示「開始追蹤」的樣子。

  如果你想要這個功能，要做兩件事：
  - 資料庫： 新增一條刪除規則，for delete to authenticated using (auth.uid() = 
    user_id)，可能還要補上 DELETE 權限（我還沒檢查過現有的權限檔）。這是一個新的
    遷移檔，要照這個共用專案的方式套用（db query --file 再 migration 
    repair），不能用 db push。
  - 前端： 在已訂閱的卡片加一個「取消訂閱」按鈕，最好有確認提示，按下後刪除那一
    列並重新整理畫面。

  設計上要先決定的一點：M2 會加入付款和 subscription_status，到時候「取消」可能
  要改成把狀態標成取消，而不是刪除整列，才能保留付款紀錄。所以你可以：
  - 現在就做刪除版，簡單，M1 夠用；或
  - 留到 M2，跟付款狀態一起設計，避免之後要改兩次。

  我的建議是，如果只是自己測試用，可以先繼續用 CLI 刪除；如果希望 M1
  對使用者是完整的，就現在補刪除版，因為它很小。要我做嗎？
