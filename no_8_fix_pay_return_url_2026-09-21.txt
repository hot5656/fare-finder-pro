     Plan: 付款後導回 localhost 而不是 Vercel 站

     Context

     從 Vercel 站付款完成後，ECPay 把瀏覽器 POST 到 flight-ecpay-result，該函式
     302 到 ${SITE_URL}/dashboard?purchase=…。

     根因（已確認，不是 bug 而是設定缺口）： Edge secret SITE_URL
     沒有設定（supabase secrets list 只有 ECPAY_*、RESEND、TRAVELPAYOUTS
     等），而 supabase/functions/_shared/ecpay.ts:22 的預設值是
     http://localhost:8080。所以不管使用者從哪個網域下單，一律被導回
     localhost。handoff doc 第 306、114 行也記載了這個預設值，當時只在 localhost
     測試所以沒問題。

     同一個 secret 還影響 flight-status-notification（index.ts:25/90）：未設定時
     email 不帶「重新訂閱」連結，這部分行為本來就是刻意的（不寄 localhost
     連結）。

     建議：讓函式依「下單網域」導回，SITE_URL 當 fallback

     只設 SITE_URL=https://fare-finder-pro.vercel.app 最快，但會讓 localhost
     測試也被導去 Vercel（專案規則是 Vercel 站還不是最終版），一個 secret
     無法同時服務兩個網域。所以：

     1. flight-subscribe：讀請求的 Origin header，對照白名單（http://localhost:8
        080、https://fare-finder-pro.vercel.app、Vercel preview 網域樣式
        https://fare-finder-pro-*.vercel.app 需先確認實際 preview
        網域格式）。通過的話放進 ECPay 的 CustomField3（目前為空字串，見
        _shared/ecpay.ts:44
        註解；CustomField1=email、CustomField2=route）。不在白名單就留空。
     2. _shared/ecpay.ts：buildCheckoutForm 多收 siteOrigin 參數寫進
        CustomField3（仍要納入 CheckMacValue，空字串也要留）。新增共用的
        allowedOrigin() 白名單函式，SITE_URL 保持 fallback。
     3. flight-ecpay-result：目前只讀 RtnCode，改為同時讀 POST body 的
        CustomField3，再驗一次白名單（這個端點沒有 JWT，body 可被偽造，否則是
        open redirect），通過才用它，否則 fallback SITE_URL。
     4. 設 SITE_URL secret 為正式站網域，作為 fallback，同時讓
        flight-status-notification 的 email 帶上重新訂閱連結（supabase secrets 
        set SITE_URL=…）。要設哪個網域由使用者決定：Vercel
        站尚非最終版，可等上線再設。
     5. 更新文件：docs/m1-session-handoff.md（第 114、306 行附近與 backlog）與
        CLAUDE.md 的 ECPay 段落，說明導回網域的決定規則。

     關鍵檔案

     - supabase/functions/_shared/ecpay.ts（SITE_URL、checkout
       form、CustomField）
     - supabase/functions/flight-subscribe/index.ts（讀 Origin）
     - supabase/functions/flight-ecpay-result/index.ts（302 目標）

     部署與驗證

     生產環境的 function 部署與 secret 設定在 auto mode
     下被擋，會給你可複製貼上的 ! 指令：

     supabase functions deploy flight-subscribe --use-api
     supabase functions deploy flight-ecpay-result --use-api --no-verify-jwt
     supabase secrets set SITE_URL=<正式站網域>   # 可延後

     驗證（用 stage 商店，不動真錢）：
     - curl flight-ecpay-result，POST
       RtnCode=1&CustomField3=https://fare-finder-pro.vercel.app → 302 到
       Vercel；CustomField3=https://evil.example → 302 回
       fallback（不能跟著走）；無 CustomField3 → fallback。
     - 從 localhost:8080 走一次完整付款 → 回 localhost；（使用者同意後）從
       Vercel 站走一次 → 回 Vercel。
     - 用 supabase functions list --output json 比對 ezbr_sha256/updated_at
       確認真的重新部署。

     待你決定

     - 白名單要包含哪些網域（是否含 Vercel preview 網域）。
     - 是否現在就設 SITE_URL，還是等 Vercel 站成為最終版再設。
     - 若想要最小改動：只做第 4 步（設 SITE_URL），代價是 localhost
       測試付款也會被導去 Vercel。

⏺ SITE_URL 是我們設在 Supabase Edge Functions
  的環境變數，用來告訴後端「我們前端網站的正式網址是什麼」。它目前用在兩個地方。

  1. 導回頁的 fallback

  付款完成後，flight-ecpay-result 會決定把使用者導回哪個網址。順序是：

  1. 先看下單時記下的網域（CustomField3）。如果在白名單內，就導回那裡。這次修好
     的就是這一條，所以你從 Vercel 站付款會回到 Vercel。
  2. 如果沒有記到，或網域不在白名單，就用 SITE_URL。

  沒設 SITE_URL 時，它預設是
  http://localhost:8080。所以萬一哪天有人從白名單以外的網域（例如 Vercel 的
  preview 網址）付款，仍會被導到 localhost。

  2. Email 裡的「重新訂閱」連結

  訂閱到期（expired）時，flight-status-notification 會寄信通知使用者。信裡只有在
  SITE_URL 有設定時，才會附上「到 <SITE_URL>/dashboard
  重新訂閱」這句話。沒設的話，信就沒有連結。這是刻意的，避免寄出指向 localhost
  的連結給真實使用者。

  為什麼說「上線前要設」

  現在沒設 SITE_URL 的影響有兩個：
  - 白名單以外的網域付款會導到 localhost。
  - 到期信沒有重新訂閱連結，使用者少了一個回來續訂的入口。

  目前只有 stage 測試，兩個影響都無所謂。正式上線時，網站會有正式網域，這時執行
  supabase secrets set SITE_URL=https://你的正式網域 就好。設定後 Edge Function
  會自動讀到新值，不用改程式碼。

  現在要不要設

  你可以現在就設成 https://fare-finder-pro.vercel.app。副作用是：從 localhost
  測試付款時，如果下單網域被記錄到就仍會回 localhost，但 email 會開始帶 Vercel
  連結。因為 Vercel 站還不是最終版，我建議等正式網域確定再設。
